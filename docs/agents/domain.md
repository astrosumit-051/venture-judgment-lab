# Domain docs

This is a single-context project.

## Before working

- Read `CONTEXT.md` at the project root when it exists.
- Read relevant records in `docs/adr/` when that directory exists.
- If either is absent, proceed silently. Create them lazily through domain modeling only after terminology or a durable decision is actually resolved.

## Vocabulary

Use the canonical terms defined in `CONTEXT.md`. Do not replace them with loose synonyms. When an important concept is missing or ambiguous, resolve it with the learner before adding it.

## Decision conflicts

If proposed work contradicts an existing decision record, surface the conflict explicitly instead of silently overriding it.
